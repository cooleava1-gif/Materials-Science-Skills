# Paper Card Workflow

1. **Establish the source boundary.** Identify available material: full
   paper, text-only, abstract/metadata, or a `materials-reader` package
   (preferred). Record the locator mode (page-grounded /
   structure-grounded / source-limited). Partial material → visibly partial
   card.
2. **Classify the paper type.** Resolve the `paper_type` axis and load its
   fragment. State the choice before analysis.
3. **Build the evidence inventory.** Enumerate: bibliographic metadata;
   research question and claimed contribution; material system and
   processing route; method components and data flow; every main figure,
   table, and essential equation with its argumentative role;
   characterization results; author-stated limitations; stable source
   pointers (pages, sections, figures, tables, reader evidence IDs).
4. **Draft the fixed Sections 01-16.** Apply core contract → paper-type
   fragment → output format, in order. Write `Not applicable` or
   `Not assessable` with a reason instead of inventing content.
5. **Calibrate claims.** Sections 09-13: tie every analytical statement to
   evidence tuples; use the shared claim-strength ladder for wording.
6. **Gate the research ideas.** Section 16 only after
   `references/research-idea-gates.md`: each idea names its evidence gap,
   a testable experiment sketch, and the boundary it respects.
7. **Delivery QA.** All 16 sections present and ordered; every
   `Not assessable` justified; evidence IDs resolve; context mode recorded;
   language matches the user.

## Output artifact

Default `paper-card.md`, one Markdown file, fixed numbered headings 01-16.

## Handoff boundaries

- Re-reading or deeper extraction → `materials-reader`.
- Bibliographic verification (Section 01/15) → `materials-citation`.
- Routing ideas into a research plan → `materials-research`.
- Re-plotting a figure at higher standard → `materials-figure`.
- Formal review simulation → `materials-reviewer` (never mixed into the
  card's critical analysis).
